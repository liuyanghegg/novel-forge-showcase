# 小说工坊 · Novel Forge

**一款会自动成长的 AI 长篇小说创作系统。**

你写一句灵感，它补全设定、拆蓝图、逐章生成；你对它提意见，它自己读、自己改、自己维护。

## 它解决什么问题

用大模型写长篇小说，写到二三十章就开始崩：人物性格漂移、伏笔忘收、前后设定矛盾、文风忽变。原因是每次生成都只带上一章，模型根本没有"这本书的记忆"。

主流做法是让人去补记忆——手写人物卡、手写大纲、反复贴设定。**很快就变成人在给 AI 打杂。**

小说工坊的思路不一样：**让系统自己维护这本书的记忆，并且让系统自己修自己的问题。**

## 核心优势：反馈闭环 —— 用户提意见，AI 自己改

这是我们和所有同类产品最本质的区别。

### 传统 AI 写作工具的反馈流程

```
用户发现问题 → 用户自己描述 → 用户自己判断 → 用户自己改提示词/设定 → 用户自己验证
```

整个闭环全部压在用户身上。用户成了 AI 的调试员。

### 小说工坊的反馈流程

```
用户随便说一句「这里不对」
        ↓
系统自动采集上下文（页面 / 章节 / 当时的设定快照）
        ↓
AI 巡检器读取原文，判断是否真实可采纳
        ↓
给出证据 + 严重程度 + 归类
        ↓
进入修复队列 → 修复 → 自动回复用户「已修复，改动是这些」
```

**用户只需要表达"哪里不舒服"，剩下的判断、定位、修复、回复、验证，系统自己做。**

### 这套机制的几个关键设计

**1. 判定由模型主导，不靠关键词**

很多系统的"反馈自动分类"是关键词匹配——写了"不好用"就归类为体验问题。这会误杀，也会被绕过。

我们的巡检器会把反馈原文 + 页面上下文 + 相关章节内容一起交给模型，让它给出：
- `actionable`：是否真的可以采纳
- `severity`：影响程度
- `evidence`：**支撑判断的具体依据**（这一项为空则判定无效）

**2. 结论必须带证据，无证据即无效**

模型说"这是有效反馈"不行，必须说清楚"因为第 7 章里主角的眼睛颜色在这里变成了黑色，与第 3 章设定冲突"。

没有证据的判定一律作废，降级为待人工复核。

**3. 规则只做兜底，明确标注**

模型不可用（超时 / 没配 Key / 返回非法 JSON）时才走规则层，并且结论会标记 `fallback`，让你事后知道"这条不是模型判的"。

**4. 无论接受还是驳回，都给用户回复**

不采纳也要说清楚为什么不采纳。用户不会对着一个"已处理"的标签猜。

**5. 重复反馈自动合并**

同一个问题被多个人提，自动识别为重复并归并，不会变成十条待办。

### 这意味着什么

| | 传统工具 | 小说工坊 |
|---|---|---|
| 谁发现问题 | 用户 | 用户（随便说一句就行） |
| 谁定位问题 | 用户 | **系统** |
| 谁判断要不要改 | 用户 | **系统（带证据）** |
| 谁执行修复 | 用户 | **系统** |
| 谁回复用户 | — | **系统** |
| 谁验证修复有效 | 用户 | **系统 + 用户确认** |

**产品的质量不取决于用户会不会调教，而取决于系统会不会自省。**

## 除了反馈闭环，还有什么

### 写前必读，不是无脑续写

每章生成前，系统强制读取：

- 世界硬规则（不可违反的底层设定）
- 本章蓝图（目标 / 场景节拍 / 出场实体 / 禁用内容）
- 相关人物的最新状态（15 维事实快照）
- 未回收的伏笔清单
- 前章摘要链 + 前章尾段原文
- 文风约定

缺任何一类，模型就只能即兴发挥，长篇必崩。这是架构层面的强制，不是提示词里的一句"请注意"。

### 门禁：不合格的章节落地不了

章节写完后要过检查：

- 字数是否达标
- 是否引用了不存在的实体
- 是否违反了硬规则
- 是否出现禁用词 / 禁用桥段
- 事实是否与快照矛盾

不过就重写，重写不过就记录失败原因，而不是把垃圾塞进正文。

### 事实快照：长篇不漂移的底座

每章落地后，系统抽取并更新 15 个维度的事实：人物状态、位置、外貌、物品、地点、势力、秘密、誓约、冲突、时间线、截止期限……

下一章生成时带的是**最新快照**，不是原文堆砌。这让写第 80 章时依然知道第 3 章定下的规矩。

### 伏笔账本

埋了什么、在哪一章埋的、多久没回收，全部记账。超过阈值自动告警。回收时需要显式引用原伏笔编号，防止"假装回收"。

### 蓝图可编辑，AI 不独占控制权

- 每章蓝图可视化编辑，改完生成新版本，旧版可回溯
- 正文手工编辑产生新修订，不覆盖历史
- AI 改稿只给候选，绝不自动覆盖你的正文

**AI 是助手，不是主人。**

### 对话式改稿

用自然语言改设定：

> 「把程野的欲望改成找回父亲留下的旧船」

系统会：读人物档案 → 修改 → 告诉你「影响了第 1、2 章，因为正文里提到了他」。

不是装作改了，是真改，并且告诉你连锁影响。

### 模型自己配，不绑死

- 支持 OpenAI 兼容 / OpenAI 官方 / Anthropic / Gemini
- 每个账号配自己的端点和 Key，互不可见
- Key 只在服务端持有，接口只返回脱敏值
- 建书前可测连通性

**不内置任何默认上游**，你不必为了用它而把 Key 交给第三方。

## 界面

### 作品列表
清晰的卡片视图，每本书显示类型、目标字数、作业次数、当前状态。

### 章节工作台
三栏切换：正文（可编辑、版本化）、蓝图（目标/节拍/实体）、版本（历史对比与回退）。

### AI 助手
右下角常驻入口。快捷提问 + 自由对话，每次操作显示工具调用轨迹（✓ 读取事实快照 · ✓ 修改人物档案）。

### 故事资料库
人物、地点、势力、道具、秘密、事件、伏笔统一聚合，支持搜索。

### 连贯性验收
19 项维度自动检查，输出可下载的报告。

### 反馈中心
提交反馈、附带截图、查看处理轨迹、收到系统回复。

## 常见问题

**Q：和直接用 ChatGPT 写小说有什么区别？**

ChatGPT 没有这本书的记忆。它每次都在重新认识你的角色。小说工坊每章都带着最新的事实快照、伏笔账本和蓝图，写到第 80 章依然知道第 3 章的规矩。

**Q：和 Sudowrite / NovelAI 这类工具有什么区别？**

它们的重心在"单章写得好"。我们的重心在"整本书不崩"，以及**系统能自己发现问题并修**。反馈闭环是本质差异。

**Q：AI 会不会乱改我的正文？**

不会。AI 改稿只返回候选，必须你点了"采用"才会保存，并且保存为新版本，旧版永远可回。

**Q：我的 Key 安全吗？**

Key 存在你自己的账号库，接口只返回脱敏值（`sk-1…abcd`），不写日志。其他账号查不到。

**Q：现在能稳定用吗？**

目前在公开测试阶段。生成流水线、门禁、快照、回滚、反馈闭环都已跑通并有自动化验收；但长任务（一次性生成几十章）的稳定性仍在实测中，建议先小批量试。

**Q：会开源吗？**

暂不开源。这个仓库用于发布版本说明、已知问题和收集反馈。
